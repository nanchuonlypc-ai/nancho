# 난초 (NANCHO) — THE MIDNIGHT LOG

자정에만 잡히는 주파수를 받아적는 기록실. 바닐라 HTML/CSS/JS + Supabase + Cloudflare Pages.

---

## 1. 배포 순서 (처음 한 번)

### ① Supabase — SQL 한 번 돌리기
프로젝트(`wtwibpchtbjwiuvzaybh`)는 이미 연결돼 있습니다. **표(테이블) 만들기만 하면 끝:**
1. Supabase 대시보드 → 왼쪽 **SQL Editor** → **New query**
2. `supabase_setup.sql` 파일 내용을 **전부** 붙여넣고 **Run**
   - 테이블·권한·난초 기본값이 한 번에 들어갑니다.
   - 여러 번 실행해도 안전합니다(기존 편집 내용을 지우지 않음).

### ② `supabase.js` — ✅ 이미 채워져 있습니다
프로젝트 `wtwibpchtbjwiuvzaybh` 기준으로 주소·키가 들어가 있어 따로 손댈 게 없습니다.
나중에 프로젝트를 옮기면 이 파일 상단 두 줄만 바꾸면 됩니다.
```js
const SUPABASE_URL  = 'https://wtwibpchtbjwiuvzaybh.supabase.co';
const SUPABASE_ANON = 'eyJhbGciOi...';
```
> anon 키는 원래 브라우저에 공개되는 키라 소스에 있어도 괜찮습니다. 다만 **service_role 키는 절대 넣지 마세요.**

### ③ 관리자 계정 만들기
Supabase → **Authentication → Users → Add user**
- 이메일·비밀번호 입력, **Auto Confirm User 켜기**
- 이 계정으로 `/admin` 에 로그인합니다. **비밀번호는 소스에 들어있지 않습니다.**
- 비밀번호 변경·분실·관리자 추가는 전부 Supabase 대시보드에서 처리합니다.

⚠️ **순서 주의** — 계정을 만들기 전에 SQL 을 먼저 돌리면, 쓰기 권한이 로그인 사용자로 잠겨
본인도 관리자에서 저장할 수 없습니다. **계정 생성 → SQL Run** 순서를 지키세요.

### ④ GitHub 업로드
아래 구조를 **그대로** 올립니다. (`fx.js`·`site.js`·`style.css`·`supabase.js`는 루트)
```
index.html  style.css  fx.js  site.js  supabase.js  supabase_setup.sql
assets/                       ← 배경 이미지 6장 (webp)
admin/index.html              ← 관리자
overlay/index.html            ← OBS 오버레이
profile/  notice/  schedule/  work/  diary/  song/  dress/  game/   (각 index.html)
.github/workflows/keepalive.yml
```

### ⑤ Cloudflare Pages 연결
**Workers & Pages → Create → Pages → Connect to Git** → 저장소 선택 →
- Framework preset: **None**
- Build command: **비움**
- Output directory: **비움 (또는 `/`)**
→ **Save and Deploy**. 1~2분 뒤 `https://xxxx.pages.dev` 로 열립니다.

### ⑥ Supabase 슬립 방지 (선택이지만 권장)
GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
- `SUPABASE_URL` · `SUPABASE_ANON_KEY` 등록
→ 매주 월·목에 자동으로 한 번 찔러 프로젝트가 잠들지 않습니다.

### ⑦ SOOP 게시글에 넣기

```html
<iframe height="5600" scrolling="no" src="배포주소/profile/"
        style="width:100%;border:0;display:block;"></iframe>
```

높이는 **픽셀**로 적습니다. `scrolling="no"` 를 빼면 안쪽에 스크롤바가 생깁니다.

**메인**은 16:9 고정 비율이라 높이를 얼마로 주든 구도가 안 깨집니다.
딱 맞추려면 `게시글 가로폭 × 0.5625`.

| 게시글 폭 | 메인 높이 |
|---|---|
| 1000 | 563 |
| 1017 | 572 |
| 1178 | 663 |
| 1200 | 675 |

**나머지 페이지**는 내용만큼 길어집니다. 아래는 **글이 하나도 없을 때**의 최소 높이이고,
글·사진이 쌓이면 그만큼 늘어납니다.

**프로필은 다시보기(VOD) 개수에 따라 크게 달라집니다.** 영상 하나가 16:9 박스라 150~350px씩 늘어납니다.

| 등록한 VOD | 폭 1017 | 폭 1178 |
|---|---|---|
| 0개 | 4365 | 4629 |
| 1개 | 4480 | 4786 |
| 3개 | 4785 | 5132 |
| 6개 | 5091 | 5479 |

**높이를 넉넉하게 주는 편이 안전합니다.** 남는 높이는 배경이 그대로 채워서 빈칸이 생기지 않습니다
(9000까지 넣어봐도 스크롤·빈칸 없음). 모자라면 바로 스크롤바가 생깁니다.
→ 프로필은 **5600** 정도로 시작하세요.

| 페이지 | 폭 1017 | 폭 1178 | 권장 시작값 |
|---|---|---|---|
| 프로필 | 4365~5091 | 4629~5479 | **5600** |
| 일정 | 1858 | 1947 | **2000** |
| 노래책 | 1489 | 1590 | 1700 + 곡 1개당 약 46 |
| 미니게임 | 1503 | 1584 | **1650** |
| 옷장 | 1018 | 1085 | 1150 + 3컷당 약 380 |
| 업보 | 1110 | 1176 | 1250 + 5명당 약 180 |
| 공지 | 953 | 1019 | 1100 + 1건당 약 60 |
| 일기 | 950 | 1017 | 1100 + 1편당 약 60 |

**정확한 값을 재는 방법** — 배포된 페이지를 브라우저로 열고 `F12 → Console` 에 붙여넣으세요.

```js
document.documentElement.scrollHeight
```

나온 숫자에 여유로 **+50** 해서 iframe 높이에 적으면 스크롤바가 생기지 않습니다.
내용을 추가한 뒤에는 다시 재서 높이를 올려주세요.

> 페이지가 부모 창에 자기 높이를 알려주는 코드(`postMessage`)는 이미 들어 있지만,
> SOOP 은 그 값을 받아 iframe 을 늘려주지 않습니다. 그래서 높이를 직접 적어야 합니다.

## 4. 관리자 사용법 — `/admin`

비번 입력 후 탭 10개.

| 탭 | 하는 일 |
|---|---|
| 🏠 메인 | 프사, 이름/읽기, 캐치프레이즈, 소개 한 줄, 메인 문구·일러, 링크 4종 |
| 🎀 프로필 | 기본 기록(나이·데뷔·생일·소속 등), About, 능력치, 마일스톤, 좋아/싫어, TMI, 채팅 규칙 |
| 📢 공지 | 공지 등록/삭제, 고정(📌) 토글, 이미지 주소 |
| 📅 일정 | 날짜·**종료일(기간 일정)**·1부/2부 시간·제목·종류(색)·굵게 표시 |

**기간 일정** — 📅일정 탭의 **종료일**을 채우면, 시작일부터 그날까지 달력에 **하나의 띠로 쭉 이어져** 표시됩니다.
(예: 여름 이벤트 주간, 장기 휴방) 비워두면 지금까지처럼 하루짜리 일정입니다.
띠는 칸 경계를 넘어 이어지고, 글자는 시작일 칸에만 나옵니다. 어느 칸을 눌러도 상세가 열려요.

⚠️ **기존 프로젝트를 쓰고 계시면** `supabase_setup.sql` 을 한 번 더 Run 해주세요 —
`ALTER TABLE schedule ADD COLUMN IF NOT EXISTS end_date DATE;` 가 들어 있어 기존 데이터를 건드리지 않고 컬럼만 추가합니다.

**요일별 편성(메인 주간 칸)** — 🏠메인 탭 아래쪽 「요일별 편성」에 `내용|시간` 형식으로 넣으면 시안처럼 요일마다 다르게 표시됩니다.
예: 월 `CHAT|21:00`, 화 `GAME|22:00`, 수 `비움`(휴방), 목 `TALK|21:00` …
한 칸이라도 채우면 위의 요일 체크박스 대신 이 표가 우선하고, 전부 비우면 체크박스 방식으로 돌아갑니다.
| ⚡ 업보 | 시청자·업보 종류 등록 → 표에서 숫자만 입력하고 저장 |
| 📓 일기 | 제목·본문·이미지, 댓글은 사이트에서 초단들이 남김 |
| 🎵 노래·VOD | 곡 개별 추가 / 벌크 추가(`제목 - 아티스트 - 장르` 한 줄씩), VOD는 **ID 숫자만**, **제목↔아티스트 일괄 교체** |
| 👗 옷장 | 이미지 주소·제목·분류(헤어/의상/렌즈/이벤트)·NEW 배지·정렬순서 |
| ✉️ 문의 | 사이트 문의 모달로 들어온 글 확인/삭제 |
| ✏️ 문구 | 화면에 보이는 **고정 문구 63곳** 전부 수정 — 섹션 제목·항목 이름·라벨·메뉴까지. 검색으로 찾기 (비우면 기본값) |
| 🎨 테마 | 프리셋 5종 · 색 6종 팔레트 · 대비 진단 · **글자 크기 4단 배율** |

**글자 크기** — 🎨테마 탭 「글자 크기」에서 디스플레이 / 섹션 제목 / 본문 / 작은 라벨을 각각 0.8~1.4배로 조절합니다.
사이트의 **모든 글자**(163곳)가 이 네 가지 중 하나에 묶여 있어 빠짐없이 함께 커지고 작아집니다.
슬라이더를 움직이면 아래 미리보기가 즉시 바뀌고, 저장하면 모든 페이지에 한 번에 적용됩니다. 1.0 이 기본값.

### 메인 화면 메뉴는 어디에?
메인은 지급받은 시안대로 **상단바에 로고 / THE MIDNIGHT LOG / MENU+** 만 둡니다.
다른 페이지·DAY 토글·문의는 오른쪽 위 **MENU +** 를 누르면 전체 화면 메뉴로 열립니다(ESC 또는 바깥을 눌러 닫기).
서브 페이지들은 기존처럼 상단에 가로 메뉴가 그대로 있습니다.

### 페이지별 영문 표기
프로필 PROFILE / 공지 NOTICE / 일정 SCHEDULE / 업보 KARMA / 일기 DIARY / 노래책 SONG BOOK / 옷장 WARDROBE / 미니게임 MINI GAME

**제목과 아티스트가 반대로 들어갔다면** — 🎵노래 탭 맨 아래 **「전체 제목↔아티스트 바꾸기」** 를 한 번 누르면 모든 곡이 한 번에 뒤바뀝니다. 잘못 눌렀으면 한 번 더 누르면 원래대로.

**🎲 랜덤 선곡** — 노래책 상단의 랜덤 선곡 버튼을 누르면 후보가 촤르륵 지나가다 한 곡에서 멈춥니다.
지금 화면에 걸러진 곡(검색어·장르 필터 적용분) 안에서만 뽑히므로, "발라드만" 같은 조건 뽑기도 됩니다.
결과 옆의 **다시 뽑기 / 복사** 로 바로 다시 돌리거나 `제목 - 아티스트` 형식으로 복사할 수 있어요.

노래책 목록은 **번호 · 제목 · 아티스트 · 난이도** 4칸입니다(장르 칸은 표시하지 않음).
장르는 필터로만 쓰이고, 등록된 장르가 한 종류뿐이면 필터 줄이 자동으로 숨겨집니다.

### 미니게임 (`/game`) — DB 불필요
- **사다리타기** — 인원 2~10명(± 버튼), 이름·결과를 직접 입력합니다.
  **결과는 처음부터 보이고, 숨겨지는 것은 가로줄뿐**입니다. 캐릭터를 누르면 지나온 길이 그려지며 내려가고,
  도착한 칸이 강조되면서 아래에 기록이 남습니다. `전부 공개`로 한 번에 볼 수도 있어요.
- **미드나잇 룰렛** — 이름을 넣고 굴리면 구슬이 코스를 따라 내려가고, **먼저 결승선을 끊는 순서대로 당첨**입니다.
  `이름*3` 으로 적으면 그 사람 구슬이 3개가 되어 확률이 3배. 당첨 인원(1~3명)과 속도(보통·빠르게·아주 빠르게)를 고를 수 있습니다.
  기본 속도에서 1등이 나오기까지 약 14초 걸립니다.
  400판 시뮬레이션으로 **자리에 따른 유불리가 없는 것**을 확인했습니다(카이제곱 검정 통과).

### 관리자 편의 기능
- **👁 이 탭 페이지 미리보기** — 지금 보고 있는 탭에 해당하는 페이지를 새 창으로 엽니다.
- **💾 백업 / 📂 복원** — 프로필·문구·색 전체를 `.json` 파일로 내려받고, 나중에 그대로 되돌릴 수 있습니다. 색을 크게 바꾸기 전에 한 번 눌러두면 안전합니다.
- **● 저장하지 않은 변경이 있어요** — 저장 전에 창을 닫으려 하면 경고합니다.
- **이미지 미리보기** — 이미지 주소 칸에 붙여넣으면 바로 아래에 그림이 뜹니다. 안 뜨면 주소가 잘못된 것(글 주소를 넣었거나 원본이 삭제됨).
- **🎨 프리셋** — 미드나잇(기본) / 체리 나이트 / 피치 워터 / 딥 오션 / 모노 실버. 누르면 6색이 한 번에 채워지고, 거기서 원하는 색만 손보면 됩니다.
- **대비 진단** — 색을 고를 때마다 "읽히는지"를 수치로 보여줍니다. **4.5:1 이상**이면 안전, `안 읽힘`이 뜨면 그 색은 피하세요.

**저장 후 사이트에서 안 보이면** → 캐시입니다. Ctrl+Shift+R.

### 이미지는 왜 "주소(링크)"로 넣나요?
이 사이트는 **서버가 없는 정적 사이트**라 파일을 받아 보관할 창고가 없습니다. 그래서 사진은 이미 인터넷에 올라가 있는 것을 **주소로 불러옵니다.**
- **용량 걱정 없음** — 사진을 사이트에 쌓지 않으니 무료 DB 용량·전송량 한도에 걸려 사이트가 멈출 일이 없습니다.
- **더 빠름** — SOOP 서버가 이미지를 대신 배달합니다.
- **바꾸기 쉬움** — 주소 한 줄만 갈아끼우면 끝.

⚠️ 대신 **원본 글을 지우면 사이트에서도 사진이 사라집니다.** 올린 글은 그대로 두세요.
(관리자 🏠메인 탭·👗옷장 탭에도 같은 설명이 접이식으로 들어 있습니다.)

### 이미지 규격 정리
| 어디에 쓰이나 | 비율 | 권장 크기 | 참고 |
|---|---|---|---|
| 밤 배경 · 낮 배경 | 가로 16:9 | 1920 × 1080 | 글자가 얹히니 너무 복잡한 그림은 피하기 |
| 메인 히어로 사진 | 가로 16:9 | 1920 × 1080 | 인물이 **오른쪽**에 오는 구도 |
| 프로필 사진(프사) | 정사각 1:1 | 400 × 400 | 움짤(.gif)은 200px 안팎으로 |
| 프로필 대표 일러스트 | 세로 4:5 | 900 × 1125 | 비우면 프사가 대신 들어감 |
| 팬 캐릭터 | 세로 4:5 | 800 × 1000 | 배경 없는 투명 PNG 권장 |
| 옷장 컷 | 세로 3:4 | 900 × 1200 | 비율이 다르면 위아래가 잘림 |
| 공지 · 일기 이미지 | 가로 3:2 안팎 | 1200 × 800 | 너무 긴 세로만 피하기 |

한 장 **1MB 아래**를 권장합니다.

### ⚠️ 디스코드·트위터 링크는 쓰지 마세요
`media.discordapp.net/...?ex=...&hm=...` 형태의 주소에는 **만료 시각**이 들어 있습니다.
붙여넣은 날에는 잘 보이지만 며칠 뒤 전부 404가 되어 사진이 한꺼번에 사라집니다.

관리자 상단의 **🔎 이미지 주소 점검** 을 누르면 등록된 모든 이미지를 확인해서
열리지 않는 것과 디스코드 링크(만료 예정 포함)를 목록으로 보여줍니다.

### 이미지 주소 얻는 법 (옷장·공지·일기)
1. SOOP **비공개 게시판**에 글을 쓰고 이미지를 업로드 → 저장
2. 올라간 이미지를 **우클릭 → "이미지 주소 복사"**
3. 주소가 `https://stimg.sooplive.com/...` 처럼 **이미지 파일 주소**여야 합니다 (글 주소 ✗)
4. ⚠️ 원본 글을 지우면 사이트에서도 이미지가 사라집니다.

**옷장 권장 규격: 세로 3:4 (예 900×1200).** 컨택트 시트가 3:4로 자릅니다.

1. OBS → 소스 추가 → **브라우저**
2. URL: `https://xxxx.pages.dev/overlay/`
3. 너비 **720** · 높이 **130**

## 6. 알아두면 좋은 것

- **다크(밤) / 라이트(주간)** 토글은 상단 `DAY`·`NIGHT` 버튼. 선택은 브라우저에 기억되어 페이지를 옮겨도 유지됩니다.
- 라이트 모드 배경은 지급받은 벚꽃 낮 이미지(`assets/nancho-day.webp`), 다크는 `nancho-purple-night.webp`. 바꾸려면 같은 파일명으로 교체하면 됩니다.
- **떠다니는 장식(플로팅)은 전부 꺼져 있습니다.** 다시 켜려면 `fx.js` 맨 위 `FX_COUNT`를 16 정도로, `FX_TILT`를 `true`로.
- 클릭할 때 튀는 입자 모양은 `fx.js` 맨 위 `FX_CLICK`.
- **방송 요일**은 아무것도 체크하지 않으면 "요일 고정 없음"으로 7칸이 모두 열립니다(난초 기본).
- 페이지를 빼려면 세 곳을 같이 지웁니다: ① 각 페이지 상단 nav ② 해당 폴더 ③ 관리자 탭.

## 8. 관리자가 안 열릴 때

관리자 페이지는 **스스로 진단**합니다. 문제가 있으면 화면 맨 위에 빨간 상자로 원인이 뜨고,
3초 안에 로그인 상자가 안 그려지면 **비상 로그인 상자**가 대신 나타납니다.

가장 흔한 원인 4가지:

0. **광고차단 확장 프로그램** — 클래스 이름이 `ad…` 로 시작하면 필터 목록이 광고로 오인해 통째로 숨겨버립니다.
   (실제로 관리자 본체 클래스가 `adwrap` 이라서 로그인은 성공했는데 화면만 사라지는 일이 있었습니다.)
   지금은 이름을 `nc-shell` · `ncApp` · `ncGate` 로 바꾸고, 표시를 인라인으로 못 박고, 로그인 후 8초간 재확인까지 합니다.
   그래도 이상하면 **시크릿 창**에서 열어 보세요 — 시크릿에서 정상이면 확장 프로그램이 원인입니다.
   ⚠️ 새 파일을 올린 뒤에는 반드시 **Ctrl+Shift+R** 로 강력 새로고침하세요(옛 파일이 캐시에 남습니다).

1. **zip을 풀지 않고 열었다** — 반드시 압축을 푼 뒤 `admin/index.html` 을 여세요.
2. **폴더 구조를 바꿔 올렸다** — `style.css` · `supabase.js` · `site.js` · `fx.js` 는 **사이트 최상위**에, `admin` 은 `최상위/admin/index.html` 이어야 합니다.
3. **캐시** — Ctrl+Shift+R (안 되면 시크릿 창).

빨간 상자에 뜬 내용을 그대로 복사해서 알려주시면 바로 잡을 수 있습니다.

## 9. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 값이 전부 기본값 | `supabase.js` 2줄 미입력 |
| 401 / 저장 실패 | URL과 anon 키가 같은 프로젝트 것인지 |
| 추가하면 404 | `supabase_setup.sql`을 아직 Run 하지 않음 |
| 저장했는데 안 보임 | 캐시 → Ctrl+Shift+R |
| 옷장·공지 이미지 안 뜸 | 글 주소를 넣었거나 원본 글이 지워짐 |
| 며칠 방치 후 안 됨 | Supabase 일시정지 → 대시보드에서 Restore + keep-alive 시크릿 등록 |
